# GA4 カスタム指標登録（Web Vitals）— Claude in Chrome 用 指示書

作成日: 2026-09-07
対象プロパティ: サウナ子（GA4 プロパティID `524886555` / 測定ID `G-EDQ38S7W3J`）
関連Issue: [#171](https://github.com/teppe049/saunako/issues/171)

## なぜ必要か

`src/components/WebVitalsReporter.tsx` が Core Web Vitals を `web_vitals` イベントで送っており、実ユーザー7,000件超のデータが溜まっている。しかし **`metric_value`（実測値）が GA4 に未登録のため数値が読めない**。

現在わかるのは good / needs-improvement / poor の3段階だけで、「INPが何ミリ秒か」が分からない。これを登録すると平均値が取れるようになり、[#171](https://github.com/teppe049/saunako/issues/171) の原因特定が進む。

**登録は遡及しない。** 登録した時点から集計が始まるので、早い方がよい。

## 🔴 「カスタムディメンション」ではなく「カスタム指標」

前回（[GA4カスタムディメンション登録](./ga4-custom-dimensions-setup.md)）は16件を**カスタムディメンション**として登録した。今回は**カスタム指標**で、タブが違う。

- カスタムディメンション: 文字列（"LCP" などのカテゴリ）
- **カスタム指標: 数値**（合計・平均・件数が自動生成される）

`metric_value` は数値なので**必ずカスタム指標**で登録する。ディメンションで登録すると平均が取れない。

## 登録するもの（1件）

| 指標名 | イベントパラメータ | 測定単位 | 説明 |
|---|---|---|---|
| metric_value | `metric_value` | **ミリ秒** | Core Web Vitalsの実測値。LCP/INP/FCP/TTFBはミリ秒、CLSは1000倍した整数 |

上限は50件/プロパティ。**カスタム指標は削除できない（アーカイブのみ）**ので、パラメータ名を正確に入力する。

## 登録しないもの

- `metric_name` / `metric_rating` — カスタムディメンションとして登録済み。読める
- `metric_id` — 同一メトリクスをグループ化するためのIDで、集計対象ではない

## 手順

### 1. カスタム定義の画面を開く
https://analytics.google.com/ を開き、左下の歯車「管理」をクリック。
「データの表示」列にある「カスタム定義」を開く。

プロパティ選択画面が出たら「サウナ子」（524886555）を選ぶ。

### 2. 「カスタム指標」タブに切り替える
画面上部にタブが並んでいます。デフォルトは「カスタム ディメンション」なので、
「カスタム指標」タブをクリックして切り替えてください。

切り替えたら、現在登録されているカスタム指標の一覧を報告してください
（0件かもしれません）。

### 3. 既存を確認する
一覧に metric_value という指標が既にあれば、作成せずにその旨を報告して終了してください。

### 4. カスタム指標を作成する
「カスタム指標を作成」ボタンを押し、以下を入力する。

  指標名        : metric_value
  説明          : Core Web Vitalsの実測値。LCP/INP/FCP/TTFBはミリ秒、CLSは1000倍した整数
  イベント パラメータ: metric_value
  測定単位      : ミリ秒

イベントパラメータは候補リストに出てこなくても手入力で確定してください。

測定単位のプルダウンには「標準」「時間」「距離」「通貨」などの区分があります。
ミリ秒は「時間」の中にあります。見つからない場合は、選択肢をすべて報告してください。

### 5. 保存する
「保存」を押し、一覧に戻ることを確認する。

### 6. 確認
カスタム指標の一覧のスクリーンショットを撮ってください。

## 登録後にこちらで確認すること

登録は遡及しないため、**すぐには値が入らない**。24〜48時間後に以下で確認する。

```
GA4 Data API の runReport で
  metrics: [{ name: "averageCustomEvent:metric_value" }]
  dimensions: [{ name: "customEvent:metric_name" }]
```

`averageCustomEvent:` プレフィックスが平均値。`customEvent:` は合計値になる。

これで「LCPの平均が何ミリ秒か」が読めるようになり、[#171](https://github.com/teppe049/saunako/issues/171) の Phase 2（ページ別・デバイス別の分解）に進める。

なお75パーセンタイル（Googleの合格判定に使われる値）は Data API では計算できない。必要なら BigQuery へのエクスポートが要る。
